# RP2 / T3 — Veri kaynağı olayları, sentetik alan düzeyinde kaynak, veri sağlayıcı arayüzü

Dal: `rp2/t3-source` (`rp2/int` üstünde). Yazılan yerler: `crates/qp-source/`,
bu dosya. `qp-schema`'ya dokunulmadı (şema notları §6).

## 1. Ne yapıldı

`qp-source`'a dört modül eklendi (eski `SeriesSource` / `BarEvent` / dosya kaynağı aynen
duruyor; `SourceError::new` artık `pub`):

| Modül | İçerik | Şartname |
|-------|--------|----------|
| `feed.rs` | `FeedStore`: bir beslemenin barları + son uygulanan `seq` + boşluk durumu; `DataEvent`'leri §18.4 kurallarıyla uygular ve ne olduğunu kesin söyler; artımlı (tembel) veri özeti ve `DataPosition` | §18.3, §18.4, §18.5 |
| `window.rs` | `resolve_window`: pencere çözümü (son n, `from_t`, `from_t..to_t`), çapa, `max_bind_bars` kesmesi ve nedeni, kapalı pencere bilgisi, depo sınırları | §18.2, §18.7 |
| `provider.rs` | `SourceProvider` (nesne güvenli, G/Ç varsayımsız), `Resolution`, bağ doğrulaması (`validate_id`, `validate_interval`, `validate_binding`), `bind` (motor tarafı çözüm: doğrula → sağlayıcı → pencere/kesme → `FeedStore`), `MemoryProvider` (`InitData`'dan) | §18.3, §18.6, §18.7 |
| `events.rs` | `SyntheticEvents` (tohumlu alan düzeyinde akış, isteğe bağlı geçmiş düzeltmeleri), `data_events_from_bar_events` (eski `BarEvent` akışından çevirici), `bar_patch_diff` | §18.4, kabul ölçütü 3 |

Ayrıca `crates/qp-source/MATRIKS_MAPPING.md` (Matriks eşleme değerlendirmesi, kabul
ölçütü 3, uygulanmadan) ve `crates/qp-source/examples/feed_bench.rs` (ölçüm).

## 2. API özeti

                   Gap{expected, got}, Stale(StaleReason), OutsideWindow{t} }
pub enum StaleReason { Gap{expected, got}, Limit{max_bars} }   // .reason() -> String
pub enum EventError { WrongFeed{got}, UnknownFeed{feed}, BarNotAfterLast{t, last_t},
                      UnknownT{t}, EmptyPatch{t}, NonFinite{t, field}, InconsistentOhlc{t} }
pub struct TimeBounds { pub from: Option<i64>, pub to: Option<i64> }
impl FeedStore {
    pub fn new(feed: FeedKey) -> Self;
    pub fn with_bars(feed: FeedKey, bars: Vec<Bar>, seq: u64) -> Result<Self, EventError>;
    pub fn with_bounds(self, bounds: TimeBounds) -> Self;
    pub fn with_max_bars(self, max_bars: usize) -> Self;  // canlı büyüme sınırı (2 × max_bind_bars)
    pub fn state(&self) -> BindingState;                  // Ready | Stale
    pub fn stale(&self) -> Option<StaleReason>;
    pub fn reset(&mut self, bars: Vec<Bar>, seq: u64) -> Result<(), EventError>;
    pub fn apply(&mut self, ev: &DataEvent) -> Result<Applied, EventError>;
    pub fn index_of(&self, t: i64) -> Option<usize>;      // O(log n)
    pub fn position(&mut self) -> DataPosition;
    pub fn digest_u64(&mut self) -> u64;
    pub fn prefix_digest_u64(&mut self, k: usize) -> u64; // bar 0..k özeti (kanıt aralığı)
    // feed, bars, len, is_empty, seq, bounds
}

// window.rs
pub struct ResolvedWindow { pub range: Range<usize>, pub anchor_t: Option<i64>,
    pub capped: Option<String>, pub limit: Option<String>, pub anchor_missing: bool,
    pub bounds: TimeBounds, pub accepts_live: bool }

    -> Result<ResolvedWindow, String>;

// provider.rs

                      NoEntitlement{reason: String}, NoData{reason: String} }
pub trait SourceProvider {
    fn entitled(&self, principal: &str, feed: &FeedKey) -> bool;

}
pub fn validate_id(what: &str, s: &str) -> Result<(), String>;
pub fn validate_interval(s: &str) -> Result<(), String>;
pub fn validate_binding(b: &DataBinding, max_bind_bars: u32) -> Result<(), String>;

pub fn entitlement_matches(entry: &str, feed: &FeedKey) -> bool;
pub struct Bound { pub state: BindingState, pub reason: Option<String>,
                   pub anchor_t: Option<i64>, pub store: Option<FeedStore> }
impl Bound { pub fn current_state(&self) -> BindingState; pub fn current_reason(&self) -> Option<String>; }
pub fn bind(provider: &dyn SourceProvider, principal: &str, binding: &DataBinding,
            max_bind_bars: u32) -> Result<Bound, String>;
impl MemoryProvider {
    pub fn new() -> Self;
    pub fn from_init(init: &InitData, root: &Path) -> Result<Self, SourceError>;
    pub fn add_feed(&mut self, feed: FeedKey, bars: Vec<Bar>) -> Result<(), SourceError>;
    pub fn entitle(&mut self, principal: &str, entries: impl IntoIterator<Item = String>)
        -> Result<(), SourceError>;
    pub fn set_pending(&mut self, feed: FeedKey);
    pub fn feed(&self, feed: &FeedKey) -> Option<&FeedStore>;
    pub fn apply(&mut self, ev: &DataEvent) -> Result<Applied, EventError>;
}

// events.rs
pub fn bar_patch_diff(old: &Bar, new: &Bar) -> BarPatch;

pub struct SyntheticEventsConfig { pub n, pub seed, pub ticks_per_bar, pub start,

impl SyntheticEvents { pub fn new(feed: FeedKey, cfg: SyntheticEventsConfig) -> Self;

## 3. Verilen kararlar (T4 ve şartname için)

1. **Denetim sırası** (`FeedStore::apply`): besleme → yineleme (`seq` ≤ son, içerik
   bakılmaz, eşgüçlü) → bayatlık/boşluk → değişimin kuralları.
2. **Reddedilen olay `seq`'i ilerletmez.** Depo kaynağın bir adımını kaçırmış olur; bir
   sonraki olay `Gap` olarak bildirilir ve barındırıcı yeniden çözer. Gerekçe: reddedilen
   olaydan sonra deponun kaynakla aynı veriye baktığı söylenemez. §18.4 artık bunu
   açıkça söylüyor.
3. **Boşluktan sonra depo `reset`'e kadar bayattır** (`BindingState::Stale`,
   `StaleReason::Gap`); eksik `seq` sonradan gelse bile uygulanmaz, bayatken gelen her
   (yineleme olmayan) olay `Applied::Stale(neden)` döner ve `seq`'i ilerletmez. Yineleme
   yine `Duplicate`'tir.
4. **OHLC tutarlılığı** zorunlu: `bar` olayının barı ve `patch` sonrası bar
   `qp_schema::validate_bars` kuralını (`h ≥ max(o,c)`, `l ≤ min(o,c)`, `l ≤ h`) sağlamalı,
   yoksa `InconsistentOhlc`. Böylece depodaki her bar her zaman geçerli. §18.4 ve §18.7
   artık bunu söylüyor.
5. **Pencere sınırları** (`TimeBounds`): bir pencereyi tutan depoda sınır dışındaki
   zamana ait olay (kapalı pencereye `to_t`'den sonraki bar, çapadan önceki bara düzeltme)
   hata değil `OutsideWindow`'dur ve `seq`'i ilerletir — aksi halde pencere filtresi sahte
   boşluk yaratırdı. Sınırsız depoda (tüm besleme) olmayan `t` hatadır.
6. **`bind` sağlayıcıya güvenmez**: sağlayıcının verdiği barlara pencereyi yeniden
   uygular, `max_bind_bars` ile keser (en son barlar; `reason`), boş sonucu `no_data`
   yapar, barları doğrular.
7. **Aralık kuralı yerel**: `qp-source` `qp-calendar`'a bağlanmıyor (yalnız
   geliştirme bağımlılığı). Gerekçe: `qp-source` `qp-render` → `qp-wasm` zincirinde; takvim
   tablolarını WASM paketine sokma riskini almamak. Kural birebir aynı, bir test her aday
   değerde iki işlevi karşılaştırıyor (`interval_rules_match_qp_calendar`).
8. **Sağlayıcıda yetki bekleme durumundan önce denetlenir** (yetkisiz kişiye beslemenin
   varlığı sızmaz).
9. **Özet tembel ve önek önbellekli**: `prefix[k]` = bar 0..k'nin FNV durumu. Değişen ilk
   bardan sonrası kesilir, özet istendiğinde uzatılır. Bellek: bar başına 8 bayt.
   `prefix_digest_u64(k)` kanıt aralığının (bar 0 → olgunun barı, §18.5) özetini de O(1)
   (önbellek sıcaksa) verir. Adım artık `qp_schema::data::data_digest_extend` (−0.0'ı 0.0
   gibi özetler); yerel kopya kaldırıldı.
10. **Çapa** (T2 denetimi sonrası, §18.3): bağda `anchor_t` varsa `resolve_window` ve
   `bind` çapadan çözer (`t ≥ anchor_t`, kapalı pencerede `≤ to_t`); `last` yalnız ilk
   çözümün büyüklüğüdür, başı kırpmaz. Çapadan bu yana `max_bind_bars`'tan çok bar varsa
   kırpılmaz: `Bound.state = Stale`, `reason` "limit…", `store` yok, `anchor_t` bağınki.
   Kaynakta tam `anchor_t`'de bar yoksa (geçmiş kısalmış) bar 0 sonraki bardır; durum
   `Ready`, `reason` bunu söyler (`anchor_missing`) — açık soru, §6.
11. **Canlı büyüme sınırı** (§18.7): `bind` depoyu `with_max_bars(2 × max_bind_bars)` ile
   kurar. Depo bu kadar bar tutarken gelen yeni bar uygulanmaz, `seq` ilerlemez, depo
   `Stale(Limit)` olur ve sonraki olaylar da öyle döner (en çok `2 × max_bind_bars` bar
   tutulur). `Bound::current_state()` / `current_reason()` depo durumunu verir.
12. **Veri yetkisi biçimleri** (§18.3): `*`, `SYMBOL` (her beslemede, varsayılan dahil),
   `feed/SYMBOL` (yalnız o adlı besleme), `feed/*`. `MemoryProvider::entitle` ve
   `from_init` geçersiz girdiyi reddeder (hiçbiri verilmez); `entitlement_matches`
   geçersiz girdiyi hiçbir şeyle eşlemez.

## 5. Ölçümler

Yerel, Apple M4 Max, `--release`, `cargo run --release -p qp-source --example feed_bench`
(iki koşu; ikincisi). `rp2/int` birleştirmesinden (şemanın −0.0 düzeltmesi, ortak özet
adımı) sonra yeniden koşuldu: olay uygulama 25.4 ns, ekleme + `position()` 120 ns, canlı +
`position()` 124 ns, düzeltme bar 0/5000/9990: 486 µs / 244 µs / 0.57 µs, baştan özet
487 µs. Fark gürültü düzeyinde. İlk ölçüm:

| İşlem (10.000 bar) | Süre |
|--------------------|------|
| Olay uygulama, alan düzeyinde akış (10.000 bar × 10 tik = 100.000 olay, 5 koşunun en iyisi) | **23.6 ns/olay** |
| Canlı güncelleme, yalnız `apply` | 46 ns |
| `index_of` (ikili arama) | 17 ns |
| `data_digest` baştan (10.000 bar) | 486 µs (ilk koşu 674 µs) |
| 1 bar ekle + `position()` | **124 ns** |
| Canlı güncelleme + `position()` | **124 ns** |
| Düzeltme bar 9990 + `position()` | 0.56 µs |
| Düzeltme bar 5000 + `position()` | 241 µs |
| Düzeltme bar 0 + `position()` | 485 µs (≈ baştan) |

Okuma: ekleme ve canlı güncellemede özet maliyeti bar sayısından bağımsız (O(1); 124
ns'nin çoğu `DataPosition`'ın dize biçimlemesi ve `FeedKey` kopyası). Düzeltme bar *i*'den
sonrasını yeniden özetler, O(n − i): beklenen ve belgelenen maliyet. Baştan özet ~48 ns/bar
(FNV-1a bayt bayt, 48 bayt/bar); bu `qp_schema` algoritmasının bedeli. Sık düzeltme olan
bir beslemede `position()`'ı her olayda değil yayın anında istemek yeter (önek tembel).

## 6. Şema ve şartname notları (orkestratöre; `qp-schema` değiştirilmedi)

T2 denetimi sonrası (`rp2/int` 080cbcf) **kapananlar**: FNV adımı dışa açıldı ve
kullanılıyor; §18.4 artık reddedilen olayın `seq`'i ilerletmediğini, tutarsız OHLC'nin
reddedildiğini, pencere dışı olayın yok sayılıp `seq`'i ilerlettiğini ve kontrol sırasını
söylüyor — uygulama metinle aynı (bkz. §3 karar 1–5).

**Açık kalanlar / yeni bulgular:**

1. **`rp2/int`'te clippy kırmızı.** `crates/qp-schema/src/data.rs:253`
   `const FNV_OFFSET: u64 = DATA_DIGEST_OFFSET;` yalnız testte kullanılıyor; test dışı
   derlemede `dead_code` → `cargo clippy --workspace --all-targets -- -D warnings` hata
   veriyor (bu dalda da). Öneri: sabiti silip testte `DATA_DIGEST_OFFSET` kullanmak ya da
   `#[cfg(test)]`. `-A dead_code` ile çalıştırınca başka uyarı yok.
2. **§18.7 ile §18.4 çelişiyor.** §18.7: "Kapalı pencereye (`to_t`) `bar` olayı uygulanmaz
   (barındırıcıya **hata**)"; §18.4: pencere dışı olay (kapalı pencerede `to_t`'den sonraki
   `bar`) **yok sayılır ve `seq`'i ilerletir**. Uygulama §18.4'ü izliyor
   (`Applied::OutsideWindow`, hata değil; barındırıcı isterse bunu bildirir). §18.7'deki
   cümlenin "uygulanmaz (yok sayılır, `seq` ilerler)" olarak düzeltilmesi önerilir.
3. **Çapalı çözümde sınır: `max_bind_bars` mı `2 × max_bind_bars` mı?** Talimata göre
   çapadan bu yana `max_bind_bars`'tan çok bar varsa `stale`. Ama canlı büyüme `2 ×
   max_bind_bars`'a kadar `ready` kalıyor; otorite yeniden başlarsa, örneğin 1,5 ×
   `max_bind_bars` bar tutan ve o ana kadar `ready` olan bir bağ yeniden çözümde `stale`
   olur. Tutarlılık için çapalı çözüm sınırının da `2 × max_bind_bars` olması önerilir (tek
   satırlık değişiklik: `window.rs`'deki `limit` koşulu). Karar şartnamenin.
4. **Kayıp çapa barı tanımsız.** Sağlayıcının geçmişinde tam `anchor_t`'de bar yoksa
   (geçmiş kısalmış, bar silinmiş) bar numaraları otoriteninkinden kayar. Uygulama: bar 0
   sonraki bar, `Ready`, `reason` söylüyor. `stale` ya da `no_data` mı olmalı? §18.3'e
   bir kural önerilir.
5. **§18.6 eski yetki biçimini anlatıyor** ("kişi → semboller, `"*"` hepsi"); §18.3'teki
   `feed/SYMBOL`, `feed/*` biçimleri §18.6'ya ve `InitData.entitlements` belge yorumuna da
   yazılmalı.
6. **`InitFeed.synthetic` aralığı yok sayar**: `synthetic_bars` her zaman günlük (hafta içi)
   bar üretir; `feed.interval` `1m` olsa da barlar günlüktür. Belgelenmeli.
7. **Eksik olay türleri** (`MATRIKS_MAPPING.md` §10): bar silme; barın kesinleştiği işareti;
   "kaynak sayacı sıfırlandı / yeniden çöz" sinyali. Bugün üçü de yeniden çözmeyle
   karşılanıyor; T7 kesinleşme isterse şema genişlemesi gerekir.
8. `EventError` ve `Applied` yalnız barındırıcı tarafında (Rust tipi, protokolde yok);
   `Session::data_event` dönüşünün tel biçimi gerekiyorsa T4'te şemaya alınmalı.

## 7. Matriks eşleme özeti

Ayrıntı `crates/qp-source/MATRIKS_MAPPING.md`. Öne çıkanlar:

- `SymbolMessage` `UPDATE` (yalnız değişen alanlar) doğrudan `patch`'e oturuyor; günlük
  barda `open/dailyHigh/dailyLow/last/quantity` → `o/h/l/c/v`; gün içinde bar bağlayıcıda
  `last` ve kümülatif miktar farkından kurulur. Barı bağlayıcı kurar; motor yalnız
  `DataEvent` görür; bar kurma kuralı beslemenin parçası.
- `TradeMessage` v0'da bar kaynağı değil (f32 fiyat, anlık görüntü yok, zaman biçimi
  çelişkili); kullanılırsa fiyat `fractionCount` basamağına ondalık yuvarlanır
  (`301.55f32` → 301.54998779… → 301.55, denendi).
- `seq` yerel (Matriks QoS 0, sıra numarası belgesiz): boşluk tespiti yalnız bağlayıcı →
  motor kaybını yakalar; üst akış kaybı günlük kümülatif alanlarla (`dailyQuantity`,
  `dailyHigh/Low`) dolaylı tespit edilir.
- Yeniden bağlanma: `REFRESH` farkları `patch`; kopukluk bar sınırını aştıysa REST'ten
  eksik/değişen barlar olay olarak (yerel `seq` kesintisiz); REST yoksa ya da aralık uzunsa
  yeniden çözme. Kesinleşmiş REST barları düzeltme (`patch`) olarak gelir.
